# 编辑器待修复问题

本文档记录 `code:editor` 模块中已经确认、但暂未修复的问题。每项问题应说明触发场景、影响、原因及后续处理方向，修复完成后从本文档移除。

## KodeMirror 空白区域无法横向滚动

- 状态：待上游支持
- 影响版本：KodeMirror 0.3.5；上游 `0.3.6-SNAPSHOT` 当前实现也存在相同行为
- 影响平台：Android、iOS、Desktop

### 触发场景

关闭自动换行且代码行宽度超过编辑区域时：

- 在实际代码行上横向拖动，可以滚动代码；
- 在最后一行以下的空白编辑区域横向拖动，无法滚动代码；
- 移动端同时存在抽屉手势时，空白区域未消费的横向手势还可能被外层抽屉接收。

### 原因

KodeMirror 在编辑器内部维护一份共享的横向 `ScrollState`，但横向滚动节点分别挂在每一行代码上。最后一行以下的空白区域仅由外层布局填充，没有对应的横向滚动节点。

当前公开的 `EditorSession`、`ViewPlugin`、`Extension` 和 `Modifier` 接口均未暴露这份内部 `ScrollState`，业务层即使拦截到空白区域的拖动，也无法把滚动增量正确传递给编辑器。`scrollIntoView` 只能按光标或目标位置跳转，不能替代连续的像素级拖动。

### 当前处理

暂不采用反射、伪造光标跳转、填充虚拟代码行或复制编辑器实现等侵入式方案，继续使用现有 KodeMirror 版本，并保留该交互限制。

### 后续修复方向

优先向 KodeMirror 上游提交修复：

1. 让占满编辑区域高度的容器统一接收横向拖动，并驱动现有共享 `ScrollState`；
2. 各代码行继续使用同一状态完成测量、偏移与裁剪，但不再分别消费横向手势；
3. 保持行号栏固定，并兼容自动换行、文本选择、RTL、鼠标滚轮、触控板及外层抽屉手势；
4. 上游合入前仅使用 `mavenLocal` 验证；只有确需随业务发布且上游暂未合入时，才考虑维护内部版本。

已在上游当前实现上做过最小原型验证，相关 JVM 横向滚动测试通过，但该原型未发布，也未接入本项目。

## Android 点击编辑器无法唤起软键盘

- 状态：待定位并修复
- 影响版本：KodeMirror 0.3.5
- 影响平台：Android

### 触发场景

在 Android 真机上点击代码区域后，编辑器可以响应部分点击或光标操作，但系统软键盘不会弹起，因而无法直接输入文本。相同测试页面在 Desktop 上可以使用键盘正常输入。

### 已知边界

KodeMirror 的输入链路依赖隐藏的文本输入组件承接平台输入法，再把输入结果同步到编辑器状态。当前现象说明 Android 上的点击、焦点、输入会话或软键盘唤起链路至少有一处未正确衔接，但尚未完成根因定位，不能仅通过业务页面强制弹出键盘来认定问题已修复。

### 后续修复方向

1. 检查点击编辑区后隐藏输入组件是否真正获得焦点，并建立有效的 Android 输入法会话；
2. 检查文件切换、抽屉手势、文本选区和生命周期变化是否会意外清除焦点；
3. 修复后在 Android 真机验证首次点击、重复聚焦、键盘关闭后重新唤起及中英文输入；
4. 优先将通用问题修复到 KodeMirror 上游，避免在业务层维护另一套焦点和键盘状态。

## 中文输入法预编辑文本兼容问题

- 状态：待设计并验证
- 影响范围：所有使用输入法组合文本的场景
- 关注平台：Android、iOS、Desktop

### 触发场景

拼音等中文输入法不会把每次按键直接提交为最终字符，而是先持续更新 composing（预编辑）文本，用户选择候选词后才提交。若编辑器只按普通按键或最终字符串处理输入，可能出现：

- 预编辑文本或候选状态无法正常展示；
- 选词后文本重复、丢失或插入到错误位置；
- 删除、移动光标或替换选区后，输入法状态与编辑器内容不同步；
- Unicode 字符与编辑器偏移换算不一致，导致光标和选区偏移。

### 原因与边界

该问题与“Android 无法唤起软键盘”相互独立：即使键盘可以正常弹起，如果隐藏输入组件没有保留并正确转发 composing 区间、选区和提交事件，中文输入仍然可能异常。Desktop 和 iOS 同样可能使用带预编辑阶段的输入法，因此不能只针对 Android 做按键事件兼容。

### 后续修复方向

1. 输入桥接层以平台文本输入状态为准，完整保留 composing、selection 和 commit 变化，而不是只监听单个按键；
2. 明确 Compose 文本偏移与编辑器文档偏移的转换规则，并覆盖中文、Emoji 和组合字符；
3. 验证连续拼音输入、候选词选择、退格、光标移动、选区替换、撤销和重做；
4. 在 Android、iOS 和 Desktop 分别使用真实中文输入法验证，不能仅依赖单元测试模拟普通字符输入。
