# Schedule 系统日历投影

## 1. 当前边界

Android 与 iOS 当前都只把 Schedule 单向投影到系统日历。系统日历不是日程事实源，用户在系统日历中的修改不会回写服务端 Schedule。

受管日历名称为“掌邮日程”。Android 通过 Calendar Provider，iOS 通过 EventKit；两端都必须按应用所有权标记识别事件，不能覆盖或删除用户自己创建的同名事件。

代码中的 `CalendarOccurrenceException` 指系统日历 Provider/EventKit 对重复事件例外的原生概念，不是 Schedule 业务模型。业务层统一使用 `OccurrenceAdjustment`，两者只在投影边界进行转换。

## 2. 投影规则

| Schedule 状态 | 系统日历 |
| --- | --- |
| `TIMED` | 普通开始/结束事件 |
| `DEADLINE` | `DTSTART == DTEND` 的零时长事件 |
| `ALL_DAY` | 单日全天，使用排他结束边界 |
| `UNSCHEDULED` | 不导出 |
| TODO 已完成 | 不导出；恢复未完成后重新建立 |
| AFFAIR 关联清单后完成 | 仍按事务来源保留投影 |
| `linkedToCourse=false` 且无提醒 | 不导出 |

提醒只有一条。`minutesBefore=0` 写为准时提醒；正数表示提前分钟数。没有明确日期/时间的旧清单即使含历史提醒值也不写入系统日历。

重复 Schedule 投影为主事件；`CANCELLED` 或已完成的 TODO occurrence 投影为对应原始实例的取消例外。单次标题、日期、时间、描述和提醒等会影响系统日历的调整，在支持的适配器边界写成同一原始实例的修改例外。仅完成 AFFAIR 或仅修改分类不改变系统日历展示，不创建多余例外。

Android Calendar Provider 的对应关系如下：

| 应用内操作 | Provider 写入 |
| --- | --- |
| 创建重复系列 | 一条带 `RRULE` 的主事件 |
| 仅修改某次 | 一条例外事件；`ORIGINAL_ID` 指向主事件，`ORIGINAL_INSTANCE_TIME` 保留原始 occurrence 身份 |
| 仅删除某次 / 完成某次 TODO | 同一原始 occurrence 的 `STATUS_CANCELED` 例外 |
| 还原某次调整 | 删除对应例外行，原始实例重新继承主系列 |
| 修改整个系列 | 更新主事件，并按当前有效单次调整重新对账例外集合 |
| 修改此次及以后 | 领域层拆成前后两个系列，Provider 按两个普通主事件重新对账 |

例外身份始终使用原始发生时刻；例如每天 14:00 的 9 月 8 日被移到 16:00，例外的显示时间是 16:00，但 `ORIGINAL_INSTANCE_TIME` 仍指向 9 月 8 日 14:00。这样再次修改、取消或还原时都只命中同一次，不会误伤整个系列。

iOS EventKit 使用等价语义：先按当前 Schedule 写入系列 master，再通过 `occurrenceDate` 定位原始实例。单次修改调用 `.thisEvent` 保存，单次删除或完成 TODO 调用 `.thisEvent` 移除；修改整个系列时重建 master 并重放当前全部有效调整。iOS 额外持久化系列调整聚合指纹，只有调整集合或系列本体变化时才重建，避免每次仓库快照都重复改写 EventKit。

当前 Android 与 iOS 出站协调器均已启用原生单次例外映射。iOS 模拟器 EventKit 数据库验证到系列 master 与 detached occurrence：后者的 `orig_item_id` 指向 master，`orig_date` 保持修改前的原始发生时刻，显示时间则使用单次修改后的值。

## 3. 权限

用户第一次开启提醒时先展示“日程提醒借助手机系统日历实现”的说明，再请求平台权限。拒绝或系统未授权时，本次编辑回到不提醒。

其他设备同步来的提醒在当前设备未授权时仍保留服务端字段，信息区显示“准时（未授权）”或“提前 X 分钟（未授权）”。非编辑态也可点击并重新进入授权流程。

Android 已永久拒绝时，由 Android 平台实现弹出说明并跳转应用设置；这一判断不下沉到 commonMain。

## 4. 对账与覆盖

进入日程能力、账号切换或仓库发布新快照时，对当前账号受管日历进行对账：

```text
读取本地 Schedule 投影
  -> 读取受管日历和应用拥有的事件
  -> 按稳定事件 URI/所有权标记匹配
  -> 新建缺失事件
  -> 更新应用拥有且内容变化的事件
  -> 删除不再需要的应用拥有事件
  -> 忽略所有权不匹配的行
```

应用卸载重装后，稳定账号和 Schedule identity 仍可重新识别应用创建的行。若 Provider 中存在无法解析的旧格式行，对账不能永久卡住：只忽略非所有权行，对明确属于当前应用和账号的旧行允许重建。

## 5. 账号隔离

所有权标记必须包含稳定账号摘要和 Schedule identity。切换账号后只操作新账号对应的受管事件；旧账号事件保留在其日历中，直到该账号再次进入并按自身远端状态对账。

## 6. ICS 文件导出

设置页允许用户把当前账号的日程导出为一份 `.ics` 文件。导出使用操作发生时冻结的本地仓库快照；它只是一次性文件，不会与导入该文件的日历应用建立后续同步关系。

ICS 与系统日历共用 `ScheduleCalendarProjectionFactory`，确保以下语义一致：

- `TIMED`、`DEADLINE` 和 `ALL_DAY` 分别导出为时间段、零时长时间点和全天事件；
- 重复日程保留 `RRULE`，准时提醒使用 `TRIGGER:PT0M`，提前提醒使用负时长；
- 单次修改使用与系列相同的 `UID`，并通过原始 `RECURRENCE-ID` 定位；单次取消输出 `STATUS:CANCELLED`；
- `UNSCHEDULED` 和已完成的非重复清单不进入文件，保存成功后 UI 会告知已导出与已跳过的数量。

文件只包含日历应用展示所需的标题、描述、日期时间、重复规则、提醒和单次调整，不包含学号、token、服务端版本、本地 revision、pending 状态或失败记录。文本按 RFC 5545 转义，物理行按 UTF-8 75 octet 上限折叠。

Android 10 及以上通过 MediaStore 保存到公共 `Download/Cyxbs`，掌邮自身不申请“所有文件访问权限”。打开时通过项目已有的 FileProvider 为同一公共文件生成保留 `.ics` 文件名的只读 URI，以兼容仅按 URI 末段识别文件类型的日历应用；目标日历应用仍可能按自身实现另行申请存储权限。即使设备没有可处理 ICS 的应用，文件也会保留在下载目录。Android 8、9 使用系统文件保存面板，避免额外申请旧版外部存储权限。iOS 保存到应用沙盒的 `Documents/schedule`，随后通过系统分享面板交给目标应用；应用卸载时该内部文件会随应用数据删除。Desktop 使用系统文件保存面板，由用户选择电脑目录；Web 触发浏览器下载，最终目录由浏览器下载设置决定。Web 当前生产仓库仍是只读空仓库，保存能力已经具备，但要在接入可用日程数据后才能实际导出内容。
