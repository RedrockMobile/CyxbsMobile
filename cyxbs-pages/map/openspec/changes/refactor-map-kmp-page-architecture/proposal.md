# Proposal

## Why

地图 KMP 页面目前把地图内容、页面切换、详情浮层协调和地图图片下载流程集中在较大的入口文件中，导致导航职责和加载职责边界不清晰。需要在保持现有 UI、交互和业务逻辑不变的前提下，按地图内容与地点详情浮层拆分页面编排，并抽象下载与加载流程，降低后续维护和 review 成本。

## What Changes

- 为地图主入口和地点详情浮层明确独立的导航职责与稳定 `ContentKey`，通过详情 argument 切换地点，复用同一个详情 NavEntry 及其 ViewModel。
- 将地图页面编排整理为地图内容层与详情浮层层，保留现有横竖屏布局、搜索、图片页、返回行为和浮层显示规则。
- 抽象地图底图的缓存读取、版本判断、下载进度、缓存写入和失败处理流程，消除页面组合代码中的重复下载分支。
- 保持 Android、iOS、Desktop 的现有行为与平台加载实现；Web（JS/Wasm）不在本次范围内。
- 不改变对外导航参数协议、地图详情业务行为、缓存格式或用户可见 UI。

## Impact

- 主要影响 `cyxbs-pages/map` 的 NavEntry、详情浮层协调、地图 UI 组合和地图图片加载辅助代码。
- 可能新增地图加载流程的内部模型或协调器，但不新增跨模块公共 API。
- 需要覆盖地图模块现有 Desktop 测试，并完成 Android 编译验证；不要求 Web 构建或 UI 模拟器验证。
